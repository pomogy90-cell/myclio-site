# Контекст проекта КЛИО (для ревью и ТЗ)

## Стек и ограничения платформы
- Timeweb shared hosting, PHP 8.2, Apache, БЕЗ базы данных — всё хранится в JSON-файлах под `api/data/` (закрыт .htaccess, на сервере 403 из веба).
- Сайт — статик HTML/CSS/JS без фреймворков и без сборки. PWA — тот же подход. APK — WebView-обёртка над `/app/` (сборка отдельным Gradle-проектом, в репозиторий не входит).
- Нет Node/npm на проде. Никаких внешних CDN-зависимостей критичного пути.

## Жёсткие правила (нарушать нельзя)
1. `api/content.json` — ЕДИНСТВЕННЫЙ источник цен/карточек/сертификатов. Содержимое ЗАФИКСИРОВАНО заказчиком, при деплоях НЕ перезаливается (снапшот на сервере `api/data/content-backup-22-11-A4.json`). Правки цен — только через админку.
2. `api/data/` — живые данные и секреты (токены, ключи, бронирования). Никогда не коммитить, из веба закрыто .htaccess.
3. Журнал `api/data/manage-history.jsonl` — append-only, API изменения/очистки нет (защита от подделки истории).
4. Клиентские `app/index.html` и APK НЕ содержат модуля управления — принципиально. Модуль грузится с сервера (`/app/manage.html` → `/manage/manage.js?v=N`).
5. Ключи, keystore, пароли — никогда в репозиторий и в память агентов.
6. Перед выкладкой — обязательный прогон в браузере (консоль чистая) и сверка md5 на диске сервера.

## Архитектура модуля управления
- Бэкенд `api/manage.php`: токен-авторизация (заголовок X-Token), данные `bookings.json` {version, seq, items[]}, удаление = tombstone, события в `manage-events.json` (кольцевой буфер 300) + полный журнал в `manage-history.jsonl`.
- Фронт `manage/manage.js` + `manage.css`: режимы День/Месяц/Список, лента дат, зум сетки, bottom-sheet карточки, баланс за период, заявки, история действий, push-уведомления (FCM HTTP v1 через `api/fcm-push.php`).
- ВАЖНО: в Android WebView нативные `confirm()`/`prompt()` не работают — только свои модалки (`askYes`/`askInput` в manage.js).

## Интеграции
- FCM-пуши: проект klio-salon, ключ сервисного аккаунта на сервере в `api/data/fcm.json` (не в репо).
- DIKIDI: закрытый API, ждём одобрения партнёрской заявки. Приёмник вебхуков `api/dikidi-hook.php` развёрнут и протестирован (ping/dry/selftest), ключ диагностики — `api/dikidi-sync.php`.
- Планируются: Google Calendar, Яндекс.

## Журнал версий
Полная история приёмки с md5 — в `приёмка-md5.txt` (корень репо).
